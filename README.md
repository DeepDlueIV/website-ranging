# Website Ranging — какие форумы проверить первыми

Простая локальная программа: **список ссылок → бесплатные показатели → Excel с приоритетами**. Интерфейс на русском, без сервера, регистрации и API-ключей. Подходит для списка примерно из 100 форумов; технический предел — 1000 строк.

> Это предварительная сортировка, не измеритель посетителей. Закрытый форум без показателей получает «Нужны данные», а не «непопулярный».

## Запуск на Windows

1. Установите [Python](https://www.python.org/downloads/) версии 3.10 или новее. В установщике включите **Add Python to PATH**; компонент Tcl/Tk должен остаться включённым.
2. На странице репозитория нажмите **Code → Download ZIP**, распакуйте архив в обычную папку. Не запускайте изнутри ZIP.
3. Дважды нажмите **start.bat**. Первый запуск установит необходимые библиотеки. В открывшемся окне вставьте ссылки и нажмите **«Проверить форумы»**.

Кнопка **«Демо без Интернета»** создаёт отчёт с вымышленными данными: можно сначала посмотреть результат. Демо не требует сети после установки библиотек.

В первый настоящий запуск загружаются два справочника: ориентировочно 100 МБ суммарно, размер меняется. Дальше используется локальный кэш. Не закрывайте консоль во время проверки; используйте **«Остановить»**, чтобы сохранить частичный отчёт.

## Что подавать на вход

Можно вставить ссылки в окно или открыть **TXT, CSV, TSV, XLSX**. Один форум — одна строка. В таблице используйте колонку `url` или `Ссылка`; необязательная колонка `name` или `Название` задаёт название. У XLSX читается лист `Ссылки`, а если его нет — первый лист. Формулы в качестве ссылок не выполняются. Ошибочные строки остаются в отчёте; дубли убираются с предупреждением.

Пример:

```text
https://forum.example.com/
https://another.example.org/
```

Это условные адреса. В папке `examples` есть отдельный список публичных форумов для проверки загрузки, **не рекомендации для рекламы**. Передавайте главную страницу именно форума, а не отдельную тему. Для `site.com/forum/` рейтинг всего портала показывается только справочно: раздел не получает чужую аудиторию.

## Что получится

В выбранной папке появятся Excel, CSV и локальная `history.json`. Каждый запуск создаёт новые файлы, предыдущие не перезаписывает.

В Excel четыре листа: **Главная** — приоритеты и ручные колонки «Аудитория», «Цена», «Решение»; **Метрики** — исходные числа и объяснение баллов; **Источники** — происхождение и даты; **Как читать** — методика. Ручные пометки сохраняйте в своём Excel: в следующий отчёт они автоматически не переносятся.

Повторите проверку примерно через неделю, выбрав **ту же папку результатов**. Там, где распознаётся точный счётчик сообщений, появится чистый прирост в день. Нужны замеры с интервалом от суток; одноразовый общий счётчик не считается текущей активностью. Удаления сообщений, миграции и накрутки могут искажать прирост.

## Какие данные используются

| Источник | Что означает | Вес |
|---|---|---:|
| Google CrUX, CSV-снимок Zakir Durumeric | Диапазон популярности сайта по данным части пользователей Chrome, **не точные посещения** | 50% |
| Majestic Million | Место по числу ссылающихся сетевых подсетей; **не количество бэклинков и не посещения** | 30% |
| Открытый счётчик форума, повторный замер | Чистый прирост сообщений за день | 20% |

[CrUX: методика и лицензия Google](https://developer.chrome.com/docs/crux/methodology), [описание CSV-снимка и его ограничений](https://github.com/zakird/crux-top-lists), [Majestic: данные, лицензия и суточный лимит](https://blog.majestic.com/development/majestic-million-csv-daily/).

Атрибуция: **CrUX datasets by Google — CC BY 4.0; CSV snapshot by Zakir Durumeric. Majestic Million CSV by Majestic 12 — CC BY 3.0.** Отчёт выбирает строки источников и рассчитывает собственные производные баллы; исходные рейтинги не переименовываются в посещаемость. Приложение не связано с авторами источников и не одобрено ими.

CrUX сопоставляется с точным origin: протокол + хост. Не подставляем популярность родительского домена вместо поддомена. Для Majestic `www` сопоставляется с тем же доменом без `www`. Даты загрузки и снимка разные; месяц измерений может быть неизвестен. Снимки CrUX выходят ежемесячно, но зеркало не гарантирует немедленное обновление.

**Почему не все ранее обсуждавшиеся сервисы:** первая версия намеренно ограничена двумя пригодными бесплатными выгрузками. Cloudflare/Tranco не подключены; Common Crawl не даёт простого надёжного измерения аудитории. Скрипт не запрашивает платные SEO API.

## Как читать баллы

Каждый доступный показатель сравнивается **только с этим списком**: более популярные по данному показателю строки получают больший относительный балл. Одинаковые значения равны; единственное известное значение получает нейтральные 50. Итог — средневзвешенное доступных показателей.

**Покрытие** — сумма весов полученных показателей, а не вероятность достоверности. Например, CrUX + Majestic = 80%. При покрытии ниже 60% всегда «Нужны данные». В остальных случаях: **A** от 70 баллов, **B** от 35, **C** ниже 35. Это эвристика для порядка ручной проверки, не модель ожидаемых продаж. Изменили список — могли измениться баллы.

Закрытые и небольшие площадки часто отсутствуют в справочниках Top 1M. Это не доказательство низкой активности. У таких площадок запросите активных участников за 30 дней, просмотры рекламного раздела, географию и стоимость; затем проверяйте рекламой с отдельными UTM-ссылками.

## Ограничения и приватность

Проверяется одна открытая HTML-страница на форум с учётом редиректов и `robots.txt`. JavaScript не исполняется, авторизация и CAPTCHA не обходятся. Есть распознавание распространённых блоков статистики XenForo, phpBB, Invision и vBulletin; нестандартная верстка или язык могут остаться нераспознанными. Некоторые страницы Discourse распознаются как движок, но скрытые JS-счётчики не извлекаются.

Внешние запросы последовательные, с паузами, ограничением размера ответа и таймаутами. Выключите галочку проверки страниц, чтобы использовать только скачиваемые справочники, не обращаться к форумам. Нет центрального сервиса и загрузки вашего списка туда. При проверке сами форумы видят обычные запросы с IP вашего подключения. Системные proxy-переменные и `.netrc` не используются; в корпоративной сети это может потребовать другого подключения.

Успешно загруженный справочник используется 24 часа. При сбое обновления допускается кэш не старше семи дней с явной отметкой. Недоступность источника не подменяется нулём. Не удаляйте кэш ради частых перезагрузок: Majestic просит не скачивать выгрузку чаще раза в сутки.

`results/`, `.cache/` и `input/` исключены из Git. **Не добавляйте реальные списки, отчёты и историю в публичный репозиторий.** Эта программа предназначена для локального компьютера, не для развёртывания как публичный веб-сервис.

## macOS / Linux и командная строка

На macOS нужен Python с Tcl/Tk; на Linux для окна может потребоваться системный пакет `python3-tk`, для окружения — `python3-venv`.

```sh
sh start.sh
# Или без окна:
sh start.sh --input examples/forums.txt --output results
sh start.sh --input my-forums.xlsx --no-pages
sh start.sh --demo
```

После установки библиотек можно обращаться напрямую:

```sh
python app.py --input examples/forums.txt --output results
python app.py --demo
python -m unittest discover -s tests -v
```

На Windows тот же режим: `start.bat --input examples\forums.txt`.

## Проверки первой версии

39 автоматических тестов: загрузка файлов, нормализация, закрытые страницы, ограничения запросов, кэш, рейтинг без подмены пропусков нулём, история, Excel/CSV и демо. Сетевые ответы в тестах подставляются локально. Окно и кнопка демо дополнительно проверены в Linux с виртуальным дисплеем.

Полный живой проход по вашим форумам ещё не выполнен; реального списка пока нет. Среда разработки не позволяла выполнять исходящие HTTP-запросы самим Python-приложением. Доступность документации проверялась отдельно, но это не заменяет сетевой тест на вашем компьютере. Запуск установщика Windows также требует проверки на Windows.
